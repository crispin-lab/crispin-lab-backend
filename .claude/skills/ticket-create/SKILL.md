대화 컨텍스트(요구사항, 결정, 트레이드오프)를 한국어 Jira 티켓으로 변환한다. **외부 시스템에 쓰는 동작**이라 사용자 확정 전에는 `jira issue create` 를 호출하지 않는다.

## 인자

`$ARGUMENTS` — 선택. 비어 있으면 직전 대화에서 작업 단위를 추출한다. 값이 있으면 그 문자열을 티켓 제목 후보로 우선한다.

## 실행 순서

### 1단계: 작업 단위 식별

대화에서 다음을 추출한다.

- **무엇을 하려는가** — 한 문장으로 요약 가능한가
- **왜 필요한가** — 비즈니스/기술 동기
- **범위 경계** — 무엇이 포함되고, 무엇이 빠지는가
- **연관 모듈** — `.claude/rules/architecture.md` 기준 추정

추출이 모호하면(여러 작업이 섞여 있거나 결정이 안 끝났으면) **티켓을 만들지 말고** 사용자에게 무엇을 분리/명확화할지 묻는다. 부정확한 티켓을 만들면 정리 비용이 크다.

### 2단계: 티켓 초안 작성

다음 형식으로 한국어 초안을 만든다.

**제목 후보** — 50자 이내, 명사구 중심.
- 좋음: "lab-space:domain Page aggregate 정의"
- 나쁨: "Page 만들기" (너무 모호)

**본문 템플릿** (기존 LAB 티켓 스타일 — LAB-15 등 참조)
```
## 배경
한두 문장 prose. 왜 이 작업이 필요한가 (비즈니스/기술 동기). 불릿 X.

## 작업 범위
- 포함되는 것 (불릿). 파일·모듈 단위로 구체적으로.

## 제외 (별도 티켓)
- 명시적으로 제외되는 것 (불릿). 없으면 섹션 삭제.
```

- `## 배경` 은 prose 1-2문장. 불릿로 풀어쓰지 않는다.
- `## 작업 범위` 는 파일/모듈 단위로 구체적으로 적는다.
- `## 제외 (별도 티켓)` 은 후속 티켓이 명백히 갈리는 항목만. 없으면 섹션 자체를 삭제한다 (빈 헤더 금지).
- `완료 조건`, `관련` 같은 추가 섹션은 기본적으로 만들지 않는다. 작업 범위에서 자명하지 않을 때만 예외적으로 추가한다.

### 3단계: 타입·라벨 추정

`-t` 플래그에 들어갈 타입을 추정한다.

- 새 기능/모듈 → `작업` (이 프로젝트의 기본 타입)
- 버그 수정 → `버그`
- 의존성 업그레이드·툴링 → `작업` 으로 두되 사용자에게 한 번 더 확인

추정이 애매하면 사용자에게 묻는다.

### 4단계: 사용자 확정

다음을 보여주고 **명시적 확인**을 받는다.

```
📝 생성할 티켓 초안
   타입: <type>
   제목: <summary>

본문:
---
<body>
---

이대로 생성할까요? (y/n, 수정사항 있으면 알려주세요)
```

사용자가 수정 요청하면 반영하고 다시 보여준다. `y` 가 명확히 떨어질 때까지 호출하지 않는다.

### 5단계: 생성 호출

확정 후에만 실행한다.

```bash
jira issue create \
  -t "<type>" \
  -s "<summary>" \
  -b "<body>" \
  --no-input
```

- `--no-input` 으로 인터랙티브 프롬프트를 막는다 (필수 필드가 빠지면 실패하므로 type/summary 는 반드시 채운다).
- 본문에 줄바꿈이 있으므로 `-b` 인자는 반드시 따옴표로 감싼다. 멀티라인이 길면 임시 파일을 만들고 `--template <file>` 을 쓴다.
- 실패 시 메시지를 그대로 사용자에게 보여주고 멈춘다. 자동 재시도하지 않는다.

### 6단계: 결과 정리

생성된 티켓 키와 URL 을 사용자에게 전달한다.

```bash
jira issue view <NEW-KEY> --plain | head -5
```

생성된 키를 출력하고 (`https://crispin09.atlassian.net/browse/<KEY>`), 다음 행동을 묻는다:
- 곧바로 `/ticket <KEY>` 로 작업 시작
- 추가 티켓 생성
- 그냥 종료

## 하지 않는 일

- **사용자 확정 전 `jira issue create` 호출** — 가장 중요한 금지사항. 외부 시스템에 쓰는 동작이라 되돌리려면 `jira issue delete` 가 필요하고, 알림이 이미 나간다.
- **여러 티켓 일괄 생성** — 한 번에 하나씩. 묶음 요청이 와도 각각 확인받는다.
- **commit/PR 메시지에 들어갈 [LAB-N] prefix 자동 적용** — 별도 `/commit`, `/pr` 스킬에 위임.
- **Claude/AI/생성 도구 멘션 본문에 포함** — `.claude/rules/commit.md` 와 동일 원칙.

## 문서 스타일

본문은 한국어. 기술 용어, 코드 식별자, 명령어, 모듈명(`lab-space/domain`, `bootJar` 등)은 원어 유지 (`.claude/rules/docs-style.md`).
