`jira-cli` 로 티켓 본문을 읽어 작업의 시작점을 만든다. **읽기 전용** 스킬이다 (Jira 상태 변경·코멘트·전이 없음).

## 인자

`$ARGUMENTS` — 티켓 식별자. 다음을 모두 허용한다:

- `12` (숫자만 — 자동으로 `LAB-12` 로 보정)
- `LAB-12`
- `lab-12`

인자가 비어 있으면 사용자에게 티켓 번호를 묻고 멈춘다.

## 실행 순서

### 1단계: 티켓 키 정규화

- 숫자만 들어오면 `LAB-` 를 붙인다.
- 소문자면 대문자로 올린다.
- 최종 형태가 `^LAB-\d+$` 가 아니면 사용자에게 다시 묻는다.

### 2단계: 티켓 본문 조회

```bash
jira issue view <KEY> --plain --comments 5
```

- `--plain` 으로 ANSI 색상을 빼고, `--comments 5` 로 최근 코멘트까지 같이 본다.
- 호출이 실패하면(인증 만료, 티켓 없음 등) 원인 메시지를 그대로 사용자에게 전달하고 멈춘다. 추측해서 진행하지 않는다.

### 3단계: 컨텍스트 요약

티켓 본문을 읽고 다음을 한국어로 요약한다.

- **제목·상태·담당자·타입** — 한 줄로
- **요구사항** — 본문에서 추출한 핵심 (불릿)
- **연관 모듈 추정** — `lab-space/domain`, `lab-space/app`, `lab-common`, `app` 중 어디를 건드릴지 (`.claude/rules/architecture.md` 기준)
- **현재 스코프 외 항목** — `.claude/rules/project-context.md` 의 "현재 스코프 외" 항목과 충돌하면 명시적으로 경고

추정에 자신이 없으면 추정하지 말고 "본문에서 명시되지 않음" 이라고 적는다.

### 4단계: 브랜치 제안

작업 브랜치명을 제안한다 — `feature/LAB-N-짧은-요약` 형식 (예: `feature/LAB-12-domain-models`).

- 영문 kebab-case, 5단어 이내, 동사보다는 명사구 (티켓 제목에서 핵심 명사 추출).
- **자동 생성하지 않는다.** 제안만 하고, 사용자가 만들지 말지 결정하게 한다.
- 사용자가 OK 하면 `git checkout -b <branch>` 를 실행한다. 이미 같은 이름 브랜치가 있으면 만들지 말고 알려준다.

### 5단계: 작업 계획 초안

티켓 유형을 추정하고 그에 맞는 체크리스트를 제시한다 (`.claude/rules/conventions.md` "PR 전 사전 리뷰 체크리스트" 참조):

- 새 도메인/모듈 → "필드 추가 PR" 또는 새 모델 골격
- 새 API → "새 API / 새 컨트롤러 PR"
- 버그 수정 → "버그 수정 PR"
- 외부 연동 → "외부 연동 PR"

체크리스트 전체를 복사하지 말고, **이 티켓에 실제로 해당하는 항목만** 골라 보여준다.

### 6단계: 다음 행동 확인

다음 중 무엇을 진행할지 사용자에게 묻는다 — 마음대로 코드 작성에 들어가지 않는다.

- 브랜치 생성
- 작업 계획 더 다듬기 (Plan 모드 진입)
- 곧바로 코드 작업 시작 (어떤 파일부터 손댈지 명시 후)

## 보고 형식

```
🔑 LAB-N — <제목>
   상태: <status> · 타입: <type> · 담당자: <assignee>

📌 요구사항
- ...
- ...

🧭 연관 모듈 추정
- lab-space/domain — Page, PageRevision aggregate 추가
- lab-space/app — 추후 (이 티켓 범위 외)

⚠️ 스코프 주의
- (해당 시) lab-user/ES 검색/권한 등 현재 스코프 외 항목 충돌 경고

🌿 제안 브랜치
- LAB-N-<kebab-summary>

📋 적용 가능한 PR 체크리스트
- (작업 유형명) — 해당 항목만 발췌

➡️  다음 행동 (선택)
1) 브랜치 만들기
2) 계획 더 다듬기
3) 곧바로 코드 작업 시작
```

## 하지 않는 일

- Jira 상태 전이(`jira issue move`), 코멘트 작성, 담당자 변경 — 모두 별도 명시 요청이 있을 때만.
- 코드 작성 — 사용자 확인 전에 절대 시작하지 않는다.
- `--raw` JSON 덤프 — 사용자가 명시 요청한 경우에만.
